# Local Auth Setup (Step 14b)

Prerequisites: Node 22, Docker, Supabase CLI installed.

## 1. Configure Environment

```bash
# Copy the environment example and fill in real values
cp .env.example .env                 # Google OAuth placeholders (fill from GCP Console)
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.local.example apps/web/.env.local
```

## 2. Start Supabase Locally

```bash
supabase start
supabase db reset
```

## 3. Get the Local Anon Key

```bash
supabase status
```

Copy the `anon key` value from the output into `apps/api/.env`:

```env
SUPABASE_PUBLISHABLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

Also update `apps/web/.env.local`:

```env
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

## 4. Install and Generate

```bash
npm ci
npx -w @victenancy/api prisma generate
```

## 5. Verify

```bash
# Unit tests (no Supabase needed)
npm run test -w @victenancy/api

# Integration tests (requires Supabase + real anon key)
npm run test:integration -w @victenancy/api

# Lint all
npm run lint

# Build all
npm run build
```

## 6. Start the Stack

```bash
docker compose up --build
```

## 7. Google OAuth (Optional)

Set real credentials in root `.env` (from Google Cloud Console), then restart Supabase:

```bash
supabase stop
supabase start
```

The local Supabase callback is `http://127.0.0.1:54321/auth/v1/callback`.
The application redirect after OAuth is `http://localhost:3000/auth/callback`.

## Environment Ownership

| File | Owner | Commit? | Contains |
|------|-------|---------|----------|
| `.env.example` (root) | Developer | Yes | Placeholder OAuth vars |
| `.env` (root) | Developer | No | Real Google credentials |
| `apps/api/.env.example` | API | Yes | Placeholder Supabase vars |
| `apps/api/.env` | Developer | No | Real SUPABASE_PUBLISHABLE_KEY |
| `apps/web/.env.local.example` | Web | Yes | Placeholder browser vars |
| `apps/web/.env.local` | Developer | No | Real NEXT_PUBLIC_* values |

Never commit `.env`, `.env.local`, or the output of `supabase status`.

## Cloud Auth vs Local Auth

| Property | Local (CLI) | Cloud (managed) |
|---|---|---|
| JWT algorithm | HS256 (symmetric) | ES256 / ECC P-256 (asymmetric) |
| JWT verification | JWKS endpoint or `/auth/v1/user` fallback | JWKS endpoint only |
| JWKS endpoint | `http://127.0.0.1:54321/auth/v1/.well-known/jwks.json` | `https://PROJECT_REF.supabase.co/auth/v1/.well-known/jwks.json` |
| Issuer | `http://127.0.0.1:54321/auth/v1` | `https://PROJECT_REF.supabase.co/auth/v1` |
| OAuth callback | `http://127.0.0.1:54321/auth/v1/callback` | `https://PROJECT_REF.supabase.co/auth/v1/callback` |
| JWT signing key | Auto-generated by CLI | Managed by Supabase; independent lifecycle per project |

Each Cloud project has its own JWT signing key, OAuth client, and Auth URL.
The API's JWKS-first verification works across local and all managed environments
without code changes — only `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` change
between environments.
